## 0. Reading guide

- **Rights codes** used by opendata.swiss (they are terms of use, not licences; Swiss raw data is generally not copyright-protected):
  `terms_open` = open incl. commercial, attribution recommended · `terms_by` = attribution required · `terms_ask` = commercial use requires permission · `terms_by_ask` = attribution required **and** commercial use requires permission. CKAN `license_id` is usually `null`; the operative field is the per-resource `rights`.
- **STAC `license: "proprietary"`** on data.geo.admin.ch is the untagged default, not a restriction; the real terms are on geocat.ch or the provider's terms page.
- **Coordinate systems**: LV95 = EPSG:2056 (Swiss national, `+proj=somerc`, not supported natively by d3-geo → proj4); WGS84 = EPSG:4326; vector tiles are Web Mercator EPSG:3857 only. Several GeoJSON files put **LV95 coordinates inside a GeoJSON envelope** (RFC 7946 violation) — reproject at ingest or points land in the Gulf of Guinea.
- **Scores** 1–5: Usefulness · Visual potential · Freshness · Reliability · Ease (5 = easiest).

## 2. MeteoSwiss Open Government Data

**Platform.** MeteoSwiss runs no API of its own; OGD is published as files on swisstopo's FSDI object storage and indexed by the geo.admin **STAC API** `https://data.geo.admin.ch/api/stac/v1/` (STAC 1.0.0; collections, items, item-search). 512 collections in total, 21 `ch.meteoschweiz.ogd-*`, all with `"license": "CC-BY"`. No auth, CORS `*`, ETags present (use `If-None-Match`), cache `max-age=10`. **No per-query API before end-2026**; roadmap: Climate EDR API and Local-forecast OGC Feature API betas at year-end 2026. Docs: `https://opendatadocs.meteoswiss.ch/` (source `github.com/MeteoSwiss/opendata`); changelog RSS `https://opendatadocs.meteoswiss.ch/changelog/rss.xml` (subscribe). **V**

**Licence.** CC BY 4.0: copy, redistribute, remix "for any purpose, even commercially". Attribution `Source: MeteoSwiss` (DE `Quelle: MeteoSchweiz`, FR `Source: MétéoSuisse`, IT `Fonte: MeteoSvizzera`); no implied endorsement; excessive access may be restricted. **Weather pictogram graphics are proprietary** — only symbol numbers/descriptions may be reused. **V**

### 2.1 SwissMetNet (`ch.meteoschweiz.ogd-smn`) — V

- 158 stations; one STAC item per station (id = 3-letter code, e.g. `ber`, `lug`).
- Files: `https://data.geo.admin.ch/ch.meteoschweiz.ogd-smn/{stn}/ogd-smn_{stn}_{t|h|d|m|y}_{now|recent|historical…}.csv`; `_t_now.csv` ≈ 15 KB; `;`-separated; **Windows-1252**; timestamps **UTC** `DD.MM.YYYY HH:MM`.
- Observed today: `_t_now.csv` last-modified 19:09 UTC with last row 19:00 → ~9 min latency at 10-min cadence. Docs mention a June 2026 incident where cadence degraded to 60 min → freshness logic must tolerate this.
- Key 10-min parameters: `tre200s0` air temp °C · `tde200s0` dew point · `ure200s0` RH % · `rre150z0` precip mm/10 min · `fkl010z0`/`fu3010z0` wind m/s / km/h · `fu3010z1` gust 1 s · `fu3010z3` gust 3 s · `dkl010z0` direction ° · `htoauts0` **snow depth cm** · `prestas0` QFE, `pp0qnhs0`/`pp0qffs0` · `gre000z0` global radiation · `sre000z0` sunshine min · soil temps `tso005s0`… · `xchills0` wind chill.
- Metadata: `ogd-smn_meta_stations.csv` (LV95 **and** WGS84 columns, canton, altitude, WIGOS id), `ogd-smn_meta_parameters.csv` (182 parameters, 4 languages, units), `ogd-smn_meta_datainventory.csv`.
- **Best single endpoint:** `https://data.geo.admin.ch/ch.meteoschweiz.messwerte-aktuell/VQHA80.csv` — all stations, ~16 KB, ~10-min cadence, 21 parameters (no snow depth), `YYYYMMDDHHMM` UTC, missing = `-`.
- Sibling collections: `ogd-smn-precip` (~100 rain gauges), `ogd-smn-tower`, `ogd-nime`, `ogd-tot`, `ogd-nbcn`, `ogd-pollen`, `ogd-obs`, `ogd-phenology`.

### 2.2 Pre-rendered measurement layers on geo.admin (`ch.meteoschweiz.messwerte-*`) — V

`https://api3.geo.admin.ch/rest/services/all/MapServer/layersConfig` lists 905 layers, 59 of type `geojson` with `updateDelay`. URL pattern `https://data.geo.admin.ch/{layerId}/{layerId}_{de|fr|it|en}.json`. Verified `…lufttemperatur-10min_en.json`: 171 KB, 152 features, properties `station_name`, `value`, `unit`, `reference_ts` (ISO UTC), `altitude`, HTML `description` (treat as untrusted), **CRS EPSG:2056**. Styles at `https://api3.geo.admin.ch/static/vectorStyles/{layerId}.json`. Layers (refresh): air temperature 10 min (5 min); precipitation 10 min/1 h/24 h/48 h/72 h (5–30 min); wind speed, gust 10 min (5 min); snow depth automatic 10 min; new snow 1–3 d; total snow; sunshine; global radiation; humidity; dew point; pressure QFE/QFF/QNH; **Föhn index**; pollen (7 species, hourly); station networks incl. webcam locations (12 h). Not a documented API contract → best-effort, keep the OGD CSVs as the fallback.

### 2.3 Radar (`ch.meteoschweiz.ogd-radar-precip`) — V

- ODIM **HDF5** v2.4, **EPSG:2056**, < 1 MB per file (observed 50–110 KB), rolling **14 days**, one STAC item per day (`YYYYMMDD-ch`; today 689 assets; **tomorrow's item exists and is empty**).
- Products: `RZC` PRECIP 5-radar composite rain rate mm/h, 5 min · `TZC` PRECIP-SV · `CPC` CombiPrecip radar+gauge 60-min accumulation, 5 min (quality flag `Q`) · `CPCH` reanalysis hourly, overwrites after 8 days.
- Filenames `RZCyyjjjHHMMKK.XYZ.h5`; `KK` changes with radar availability → **list assets, never construct names**. Latency observed ~2 min.
- Decoded server-side with h5wasm in a Node route handler (verified 2026-09-08: values are float64 mm/h, `nodata` NaN outside coverage, `undetect` 0; ~30 ms decode + one-off 1.5 s Mercator lookup build; warm PNG in ~50 ms). h5wasm's virtual FS root is read-only in Node — write under `/tmp`. Hail: `ogd-radar-hail` (POH %, MESHS cm), empty Oct–Mar. Reflectivity/convection products planned end of Sept 2026.

### 2.4 Forecasts — V

- **Local forecast `ch.meteoschweiz.ogd-local-forecasting`**: same data as the MeteoSwiss app; ~6 000 points (ZIP codes, stations, peaks/passes/huts); hourly update; +0…+192 h; **CSV per parameter, all points per file** (`vnut12.lssw.{YYYYMMDDHHMM}.{param}.csv`), **Latin-1**, UTC; hourly files up to 33 MB, daily ≤ 300 KB. Parameters: temp + 10/90 % quantiles, precip + quantiles, precip probability 3 h, wind/gusts, cloud layers, sunshine, radiation, zero-degree level, weather symbol number, daily max/min. Hourly timestamps mark interval **end**; daily use local-day **start**.
- **ICON-CH1-EPS (1 km, 11 members, 33 h, 3-hourly) / ICON-CH2-EPS (2.1 km, 21 members, 120 h, 6-hourly)**: GRIB2 on CSCS object storage via pre-signed URLs from STAC search; 24-h retention (403 = expired); icosahedral grid needs separate constants files and regridding (`meteodata-lab`). Not for the MVP.
- **INCA** nowcast: data on request, LV03, not OGD.

### 2.5 Warnings — V (negative)

No STAC collection, no geo.admin layer, not on the roadmap; app endpoints 404. **Not available.** Derive our own thresholds and label them as ours.

## 3. FOEN/BAFU hydrology

### 3.1 LINDAS SPARQL — the official API — V

- Endpoint `POST https://ld.admin.ch/query` (also `lindas.admin.ch/query`), form-encoded `query=`, `Accept: application/sparql-results+json`; graph `<https://lindas.admin.ch/foen/hydro>`; cubes `…/foen/hydro/river` (200 stations) and `…/hydro/lake` (34). No auth.
- Per observation: `measurementTime`, `waterLevel` (224), `discharge` (188), `waterTemperature` (84), **`dangerLevel`** (1–5 on 181 stations, `cube:Undefined` on the rest). `isLiter` is `true` on **every** discharge row while values are plainly m³/s (Rhine at Basel 517 on 2026-09-07) → ignored (**V**). Station: `schema:name`, identifier, water body (162), geometry WKT **WGS84**.
- Observed lag ~21 min (docs: updated every 10 min). Licence `TermsOfUse/Open-Use` = "NonCommercialAllowed-CommercialAllowed-ReferenceNotRequired". Dataset `creativeWorkStatus: Draft`; `example.com` placeholder predicates; `measurementTime` carries a fixed `+01:00` offset year-round (correct as an instant — parse, don't strip). Contact `abfragezentrale@bafu.admin.ch`.
- hydrodaten.admin.ch itself has no JSON API; its "receive latest data" page points to LINDAS.

### 3.2 geo.admin hydro layers — V

`ch.bafu.hydroweb-messstationen_zustand` (200 features, 5 min), `_gefahren` (182, flood danger classes), `_temperatur`, `_vorhersage`, `hydroweb-warnkarte_national` (polygons, 2 h), groundwater layers (30 min). **Only classes and symbols, no numeric values**; EPSG:2056; HTML blobs. Use for danger colour classes; LINDAS for values. Attribution "FOEN".

## 4. Air quality — V (negative for NABEL)

NABEL (16 stations: O₃, NO₂, SO₂, CO, PM10, PM2.5, soot, VOC) has **no machine-readable current-values feed**: `nabelstationen` is WMTS raster; Meteotest query tool exports CSV manually; opendata.swiss carries only station locations; probed JSON endpoints return 403. Licence not stated. Alternatives: **Zürich UGZ** hourly CSV `https://data.stadt-zuerich.ch/dataset/ugz_luftschadstoffmessung_stundenwerte/download/ugz_ogd_air_h1_2026.csv` (12.7 MB per year, continuous; licence field null → verify); **Basel data.bs.ch** per-station realtime (CC BY 4.0, Opendatasoft Explore v2.1); Ostluft / in-Luft sites without documented APIs. No open Swiss air-quality index feed (compute Cercl'Air LQI ourselves).

## 5. Swiss Seismological Service (SED / ETH) — V

- `https://eida.ethz.ch/fdsnws/event/1/query` (SeisComP FDSNWS 1.2.7), no auth, CORS `*`; formats QuakeML (default), `text`, `csv`, `sc3ml`; **no JSON/GeoJSON** (400). `updatedafter` not implemented → poll by `starttime`. WGS84, UTC, depth km, `MLhc` magnitudes. Catalogue AD 250 → present.
- **Manually reviewed catalogue**: today an event at 03:20 got its reviewed origin at 13:22 (~10 h). Not an automatic real-time feed; filter `evaluationMode`/`evaluationStatus` in QuakeML.
- **Licence unresolved**: the SED disclaimer permits copying only for private, scientific and non-commercial use; no CC BY statement found for the catalogue. Fine for a non-commercial MVP with attribution "Source: Swiss Seismological Service (SED) at ETH Zurich"; obtain written clearance (`SED_data_access@sed.ethz.ch`) before commercial use. No open felt-report feed. geo.admin `ch.bafu.gefahren-aktuelle_erdbeben` is WMS raster only.

## 6. Public transport (opentransportdata.swiss) — V

- **Access**: free key from `https://api-manager.opentransportdata.swiss/`, `Authorization: Bearer`, mandatory `User-Agent`, follow redirects. Endpoints moved 2025-02-20 to `/la/`: TripUpdates `https://api.opentransportdata.swiss/la/gtfs-rt` (old `gtfsrt2020` deprecated), Service Alerts `/la/gtfs-sa`, SIRI-SX `/la/siri-sx`, SIRI-ET `/la/siri-et`, SIRI-PT `/la/siri-pt`, OJP 2.0 `https://api.opentransportdata.swiss/ojp20` (POST XML).
- **Rate limits** (official table): OJP 50/min, 20 000/day; GTFS-RT 5/min per limits page but 2/min per cookbook → **design for 2/min**; SIRI-ET/SX 2/min, 3 000/day; SIRI-SX planned 10/h; FEDRO 50/min on limits page but **5/min + 260 000 total** on the API-manager product page.
- **No vehicle positions**: "Vehicle Positions are not published on the Open Data Platform Mobility Switzerland"; no SIRI-VM. **No `shapes.txt`** in GTFS ("deliberately not using the shapes"). Consequence: positions must be interpolated from `stop_times` + TripUpdates along externally sourced geometry, and labelled as interpolated.
- **GTFS static** `timetable-2026-gtfs2020`: ~237 MiB zip, published Mon + Thu 09–10:00, RT switches at 15:00 (6-h mismatch window); resource UUIDs change per release → discover via CKAN `package_show`; stops WGS84.
- **Service points** (DiDok/atlas): daily CSV with `lv95East/North` and `wgs84East/North`, `fsoNumber` (BFS municipality) → join key to statistics. UTF-8 with BOM, `;`-separated.
- **Istdaten v2**: daily CSV of realised arrival/departure times per stop (~24 columns) → punctuality baselines.
- **Terms**: custom, commercial allowed, cite `opentransportdata.swiss` once in a source list.
- **Route geometry substitutes**: SBB `linie-mit-polygon` on data.sbb.ch (3 147 LineStrings, weekly, Explore API v2.1 with GeoJSON export, terms-by incl. commercial); BAV `ch.bav.schienennetz` (whole network incl. private railways; FileGDB/INTERLIS, LV95, last update Jan 2025; needs GDAL). Neither is keyed to GTFS trips → map-matching step.
- **Fallbacks**: `data.sbb.ch` `rail-traffic-information` (5 min, text only); `transport.opendata.ch` (community, undocumented rate limit, 429s) — not for production; geOps GTFS mirror (daily) and TRAVIC positions (commercial).

## 7. Road traffic (FEDRO/ASTRA via opentransportdata) — V

- **Situations**: `https://api.opentransportdata.swiss/TDP/Soap_Datex2/TrafficSituations/Pull`, SOAP pull, **DATEX II 2.2.3**, accidents/roadworks/congestion/closures from VMZ-CH, cantonal police and maintenance units; locations as **ALERT-C/TMC codes** (table `rds-tmc` dataset) — no lat/lon, no OpenLR; revoked items linger 60 min; no history; poll with `If-Modified-Since` ≤ 5 min.
- **Counters**: `…/TDP/Soap_Datex2/Pull`, **DATEX II 2.3** `MeasuredDataPublication`, every minute (published +20 s), per detector, light vs heavy vehicles, "best effort" quality.
- **Terms (FEDRO, stricter than platform terms)**: attribution "Data source: Federal Roads Office (FEDRO) Traffic Data Platform (TDP)."; commercial use with restrictions; **"transmitting data in raw format to third parties via a machine-readable interface" is prohibited** → public API may expose only derived values; standard users get 6-month access and a 260 000-call quota, then written justification or TDP-partner status (reciprocal data). Pass closures should appear as situations but coverage is **U**. `ch.astra.strassenverkehrszaehlung-uebergeordnet` on geo.admin is annual statistics only.

## 13. Cross-cutting gotchas

1. Three CRSs in play (LV95 in GeoJSON envelopes, WGS84 in LINDAS/GTFS/FDSN/SLF, 3857 tiles) → reproject once at ingest with proj4.
2. Encodings: Windows-1252 (SMN CSVs), Latin-1 (local forecast), UTF-8 with BOM (service points), UTF-8 elsewhere.
3. Timestamps: MeteoSwiss UTC in two formats; LINDAS fixed `+01:00`; Basel local time mislabelled as UTC; forecast daily params use local-day start; hourly mark interval end.
4. HTML blobs inside data properties → treat as untrusted, never render raw.
5. STAC "tomorrow" items exist and are empty; STAC `proprietary` is the untagged default.
6. Everything is file polling; nothing pushes. Use ETags and cadence-matched schedules.
7. Endpoint churn seen in 2025–26: `gtfsrt2020` → `/la/gtfs-rt`; `uvek-gis.admin.ch/BFE/ogd` → `bfe-ogd.ch`; PxWeb → SDMX; `leichte-basiskarte.vt` → `lightbasemap.vt`. Validate every payload with zod and surface failures in `source_health`.
8. Federal SLAs cover office hours only; weekends and nights have no availability commitment.
