## 2. How the architecture stays inside the limits

1. **Static generation** for every page shell; the map page is static HTML + JS and hydrates client-side. Function invocations happen only for `/api/state/*`.
2. **Mode 1 pull-through** means function work is proportional to _time with at least one visitor_, not to visitors. With CDN `s-maxage = cadence`, the function runs at most once per cadence per active region; with Swiss traffic that is one region.
3. **Mode 2 on GitHub Actions** keeps every heavy or always-on job (GTFS 240 MB, 10-min snapshots, story, radar fallback) off Vercel entirely.
4. **Basemap bandwidth is swisstopo's**, not ours. Fonts and glyphs are cached by the browser.
5. **Polling is visibility-aware and layer-aware**: hidden tabs do not poll; RAIL polls at 60 s only while RAIL or NOW is on screen; WEATHER/WATER poll at 5–10 min.
6. **Payloads are small**: normalized JSON < 100 KB gzip per layer; radar frames ~30 KB PNG; snapshots 200–500 KB gzip fetched only when the timeline is used.
7. **No middleware on hot paths** (avoids double fast-origin-transfer accounting).
8. **No database until Phase 3**, and then aggregates only.

## 3. Expected consumption and bottlenecks

Rough model to be replaced by measurements in Phases 1–2:

| Metric                     | Per visitor-hour (estimate)                                                                                    | Hobby ceiling                             | Visitor-hours/month at ceiling                                            |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------- |
| Edge requests              | first load ~40 requests + 12 weather/water polls + up to 60 rail polls ≈ 80–110                                | 1 000 000                                 | ~9 000–12 000 (≈ 300–400 visitor-hours/day)                               |
| Fast data transfer         | ~1.2 MB first load + ~15 KB × 12 + ~40 KB × 60 ≈ 3.5–4 MB                                                      | 100 GB                                    | ~25 000                                                                   |
| Function invocations       | only CDN misses: ≈ 1 per cadence per layer, independent of visitors                                            | 1 000 000                                 | not a constraint                                                          |
| Active CPU                 | rail parse ~0.3 s × up to 1 440/day ≈ 3.6 CPU-h/month worst case; weather/water/radar decode ≈ 0.5 CPU-h/month | **4 CPU-hours**                           | **the tightest limit**                                                    |
| Fast origin transfer       | ~50 KB per function response × ~50 000 responses/month ≈ 2.5 GB                                                | 10 GB                                     | fine                                                                      |
| Blob advanced ops (writes) | snapshots 4 320 + radar 8 640 + rail paths ~10 per month ≈ 13 000                                              | unknown (Pro example lists 10 K included) | **verify Hobby quota; if 10 K, thin radar writes to 10-min**              |
| GitHub Actions             | snapshot 4 320 runs × ~1 min + gtfs 8 × 10 min + story 30 × 2 min ≈ 4 500 min/month                            | unlimited (public) / 2 000 (private)      | **public repo required, or reduce snapshot cadence to 15 min on private** |
| Supabase                   | a few MB/month of aggregates                                                                                   | 500 MB                                    | years of headroom                                                         |

Likely first ceilings, in order: **active CPU (rail)** → **Blob advanced operations** → **edge requests**. All are usage caps, not bills: on Hobby, exceeding pauses the feature until the 30-day window resets, which is an outage, never an invoice.

Mitigations before any upgrade: keep the GTFS-RT parser lean (protobuf decode, no JSON round trip), precompute trip patterns in Actions so the per-minute job only joins delays, cache radar decode output for 5 min, thin snapshot writes, and measure with Vercel's usage dashboard weekly.

## 4. Where caching is mandatory

| Path                           | Cache                                                                                      | Why                                                            |
| ------------------------------ | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| `/api/state/*`                 | CDN `s-maxage=cadence, stale-while-revalidate=5×cadence` + Data Cache `revalidate=cadence` | one upstream fetch per cadence; function runs once per cadence |
| Blob assets                    | `Cache-Control: max-age ≥ cadence`, immutable for timestamped files                        | zero function involvement                                      |
| swisstopo tiles/glyphs/sprites | browser cache + swisstopo CDN (1 h)                                                        | zero Vercel involvement                                        |
| Client                         | TanStack Query `staleTime = cadence`, `If-None-Match`                                      | fewer edge requests, 304s are cheap                            |
| Upstream                       | `If-None-Match` / `If-Modified-Since` where supported (geo.admin, STAC, DATEX II)          | fewer bytes, faster refresh                                    |

Nothing is user-specific, so nothing is excluded from caching.

## 5. Upgrade path

| Trigger                                                                                                                                                 | First paid step                                                                                 | Cost                              | What it unlocks                                                                                                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| The project stops being personal/non-commercial (ads, sponsorship, company use) **or** sustained > ~300 visitor-hours/day **or** active CPU > 4 h/month | **Vercel Pro**                                                                                  | $20/month (1 seat) + usage credit | 10 M edge requests, 1 TB transfer, usage-based CPU, **per-minute crons** (Mode 2 can move back onto Vercel), 800 s functions, commercial use |
| History outgrows 500 MB or pause policy bites                                                                                                           | Supabase Pro (or Neon paid)                                                                     | $25/month                         | 8 GB, no pause                                                                                                                               |
| Team grows to 4+ people, or automated daily rendering at scale                                                                                          | Remotion Company License (Automators)                                                           | $100/month minimum ($0.01/render) | licence compliance; cloud rendering still free-ish via GitHub Actions or Vercel Sandbox                                                      |
| swisstopo fair-use ceiling approached (~20 000 users/day)                                                                                               | self-host PMTiles of the base tiles on Blob or Cloudflare R2 (free 10 GB) and talk to swisstopo | ~$0–5/month                       | independence from swisstopo's fair-use                                                                                                       |
| Private repo needed                                                                                                                                     | GitHub Team or fewer Actions minutes                                                            | $4/user/month                     | more Actions minutes                                                                                                                         |

Nothing else is foreseen before roughly 50 000 monthly visitors. Approximate first paid month at that scale: Vercel Pro $20 + Supabase Pro $25 ≈ **$45/month**.
